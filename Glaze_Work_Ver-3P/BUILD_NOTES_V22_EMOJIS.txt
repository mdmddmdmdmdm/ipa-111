Glaze v22: emoji reading/sending + Emojis prompt helper
=======================================================
Not compiled (no Flutter SDK here). Run: flutter analyze && flutter test
New tests: test/emoji_text_test.dart, group 'PromptHelpers emojis' in test/prompt_helpers_test.dart

1. New Prompt Helper "Emojis" (API settings > Prompt Helpers and chat Tools; global)
   OFF by default. When on, adds one light instruction to the last system block:
   use an emoji here and there when it fits, at most one or two per reply, many
   replies none, never a string of them, none inside narration/*actions* or in
   serious moments. Saved choices from older versions load as off.
   Files: core/llm/prompt_helpers.dart, features/settings/prompt_helpers_provider.dart,
   features/settings/widgets/prompt_helpers_group.dart, assets/translations/en.json + ru.json.

2. Reading emojis (always on, independent of the helper)
   Audit result: nothing in the app strips or filters emoji; streams are decoded as
   UTF-8 chunk-safe. Two real risks fixed:
   a) Two places cut text with substring() and could slice an emoji in half
      (message_range_formatter, studio_session_state_compiler). They now use
      safePrefix() from the new core/utils/emoji_text.dart.
   b) A lone surrogate (broken emoji half from a pasted/cut string) makes strict
      servers (llama.cpp / Ollama) reject the whole request with HTTP 400.
      buildApiMessages() now replaces any lone surrogate with U+FFFD as its last step.

3. Sending emojis
   "Trim incomplete sentences" treated a reply ending in an emoji instead of a full
   stop ("I am so happy to see you 😊") as unfinished and cut that sentence off.
   A reply whose last visible character is an emoji now counts as finished
   (core/llm/reply_trimmer.dart).
