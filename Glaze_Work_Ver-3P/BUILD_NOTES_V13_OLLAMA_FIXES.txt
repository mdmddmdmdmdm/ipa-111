CODE CHANGES (4 files)
1. features/chat/services/saved_message_writer.dart  sanitizeReasoningMarkers
   - REMOVED the bare 'think>' and 'think\n' replacements. They ran on every
     final reply and deleted the plain word "think" at the end of any line
     ("what to think\n" -> "what to "; "rethink\n" -> "re").
2. core/llm/reasoning_stripper.dart  stripMessageReasoning
   - REMOVED a damaged regex  \s*Use\s\s*(?:for|to)[^.]*\.  (its <think>..</think>
     part had been lost). It matched ordinary prose, e.g. "reuse for the next
     scene." -> "re". Only affects Studio's final writer when reasoning is off.
3. core/llm/lorebook_scanner.dart  probability
   - Off-by-one fixed (probability 50 fired 51%, 0 still fired 1%).
   - An entry that loses its roll is no longer re-rolled on each recursion pass
     (a 50% entry fired ~97% of the time when recursion was on).
4. core/llm/transport/openai_chat_transport.dart
   - A mid-stream  data: {"error": ...}  frame (Ollama does this when a
     generation fails) now ends the call with that error. Before, it was
     ignored and a truncated reply was saved as a normal completion.
   - Same check for non-streaming responses.

SETTINGS TO CHANGE FOR OLLAMA (no code)
 - First-chunk timeout: 180-300 s (default 60 s is shorter than a cold model
   load or a long prompt evaluation).
 - History trim mode: "stepped" (sliding changes the prompt start every turn
   once the context is full, so Ollama's prompt cache misses every time).
 - Context size must be <= the num_ctx Ollama really runs (check `ollama ps`).
   Ollama's OpenAI endpoint cannot set it per request: use a Modelfile
   (PARAMETER num_ctx ...) or OLLAMA_CONTEXT_LENGTH.
 - Thinking models: Ollama thinks by default and thinking tokens count toward
   Max tokens (default 1500). Add extra request parameter
   reasoning_effort = "none" to turn thinking off, or raise Max tokens.
 - Keep streaming ON: with streaming off the first-chunk timeout becomes a hard
   limit on the whole reply.
 - Prompt post-processing "semi" (or "merge"): Glaze otherwise sends several
   system messages mid-conversation, including the response-instruction block
   as the LAST message; many Ollama chat templates handle that badly.

KNOWN, NOT CHANGED
 - Lorebook cooldown > 0: the current user message counts as "already matched",
   so such an entry cannot fire from the message that mentions it (a unit test
   asserts this). Leave cooldown at 0 until the intended behaviour is decided.
 - Macros {{random}}, dice, date/time change per request (and break Ollama's
   prompt cache if placed early in the prompt).
 - If the fixed prompt parts exceed the safe context, all history is dropped.
