Glaze v23: CrushOn import with full description (display + memory)
===================================================================

Problem: importing from CrushOn gave the picture but no description/details, and
tags were slightly off. CrushOn's description is a styled HTML page (banner,
pictures, coloured titles, tables), which the old reader never captured.

What changed
------------
1. assets/crushon/site_reader.js: new __gzCO.captureInfo(). On a character page it
   finds the rendered Info tab (located via the Info/Memories/Comment/Supporters
   tab row, with a biggest-text fallback), scrolls it to wake lazy images, and
   returns a cleaned copy: inline styles and pictures kept, next/image wrapper
   URLs unwrapped to the original art, scripts/handlers/buttons/iframes removed,
   plus the plain text.
2. crushon_site_reader.dart (characterPage): calls captureInfo after the page
   settles and adds it as page['info']. Failure never blocks the import.
3. NEW services/crushon_description.dart: crushonMemoryText(html) reduces the HTML
   to words only: drops pictures, styles, decorative lines (━━━), promo banners
   ("50+ Images | Astra Yao | ..."), pure titles ("Character Profile"), duplicate
   lines; decodes entities; keeps labelled lines (Personality:, Background:).
4. crushon_provider.dart:
   - the full description now beats the short blurb ('introduction') when both exist
   - two descriptions are built on import:
       DISPLAY  = the site's HTML, saved in the Creator Notes slot. The app already
                  renders that slot with pictures/colours/glow, and it is stripped
                  from the prompt, so it never costs memory.
       MEMORY   = text-only version, saved in the normal Description field that is
                  sent to the model.
   - tags cleaned: ids/UUIDs, '#', empty pieces and duplicates removed; list-card
     tags are the fallback.
5. Character editor: the Creator Notes field is now labelled "Display description
   (shown only, never sent to the model)", bigger and expandable. Edit it freely;
   the Description field above stays the model's memory.

Tests: tools/crushon_reader_test: run_tests 32 pass, calendar 9 pass, profile 1 pass,
new info_test.js (page like the Astra Yao screenshots) pass.
NOT compiled/run: Dart (no Flutter SDK here) and the live crushon.ai. Please run
  flutter pub get && flutter analyze
If the Info panel is not found on the live site the debug console prints
"[CrushOn-reader] captureInfo: ..."; send that line and the import falls back to
the JSON description / list card as before.

Favorites fix (same build)
--------------------------
Symptom: Glaze's Favorites list showed "Lily" (your OWN character, first profile tab)
instead of the starred characters.
Causes:
 a) crushon_site_reader.dart treated any URL containing "favorite" that showed cards as
    "favorites opened" - the profile ignores ?tab=favorites and shows your own
    characters. Shortcut removed; those URLs dropped.
 b) site_reader.js clicked "the 4th icon" and went on whether or not it worked. Now the
    star tab is CONFIRMED by content (Characters / World Cards / Memories / Models /
    Folders chips appear; the first tab shows All / Target / Public). The GIF button is
    excluded from the tab row; if the first guess is wrong the other icons are tried in
    turn; if none confirms, it reports "star-tab-not-confirmed" instead of reading wrong
    cards. After the Characters chip it scrolls down to the cards.
Tests: profile_test.js rewritten (wrong 4th icon, GIF button, Lily on tab 1) - pass.
