BUILD NOTES - Continue / Next message / Trim incomplete sentences / helpers (V11)
Not compiled or run in the authoring environment (no Flutter SDK there).
ApiConfig gained a freezed field, so build_runner must run (the CI already does).

1. Swipe bar always visible
   assets/chat_webview/renderer/message_renderer.js (_createFooter) and
   assets/chat_webview/bridge/chat_bridge_controller.js (_syncMessageControls):
   every character message shows the < n/m > counter, "1/1" with one variation.
   Greeting switcher (first message with several greetings) and error bubbles
   behave as before. Right arrow on the last message at its last variation
   still regenerates a new variation (existing behaviour).

2. Continue button (composer row, right after F)
   ComposerAction.continueMessage (fast-forward icon). Tap = ChatNotifier.continueMessage()
   (existing: same message grows, no new message).
   Long-press opens a sheet:
     - Remove last continuation: cuts the message back to message.continuationOffset
       (recorded by the continuation merger), via editMessage. Earlier continuations stay.
     - Redo continuation: removes the last continuation, then continues again.
   Existing installs get the button slid in once, after F (pref
   composer_pins_continue_seeded_v1). It is also a card in the Actions tab if unpinned.
   Limit: only the most recent continuation is tracked, so remove works once per Continue.

3. Next message button (beside the send button)
   Up-arrow circle button in the accent colour. ChatNotifier.generateNextMessage():
   appends a NEW assistant message after the last assistant message, with the
   instruction kNextMessageInstruction (preset_defaults.dart) injected at the end
   of the prompt through the same slot Continue uses. If the user spoke last it just
   replies to that message. New flag `nextMessage` is threaded
   chat_provider -> generation_pipeline -> chat_generation_service -> stream_generation_service.

4. Trim Incompl. Sentences
   New per-API switch under Max Output Tokens (ApiConfig.trimIncompleteSentences,
   default off). Logic: lib/core/llm/reply_trimmer.dart (ReplyTrimmer.trimIncompleteSentences):
   cuts after the last real sentence end, ignores Dr./3.5/J. Smith/"Where?" she asked,
   closes *action* and "dialogue" left open by the cut, never empties a reply.
   Applied in StreamGenerationService._postProcessReply (main generation path;
   not applied to Studio output or aborted partial replies).

5. Prompt helpers (Short / Medium / Long, Enforce user agency)
   - Instruction wording made stricter with word/paragraph targets (prompt_helpers.dart).
   - Code-level backstop after generation (same _postProcessReply):
       user agency (or user name accuracy) on: cut where the reply starts a "Name:" line
       or a sentence outside quotes that opens with the persona name + an action word.
       Short: keep at most 3 blank-line-separated paragraphs when over 150 words.
       Medium: at most 7 paragraphs when over 420 words.
       Long: no cap.
   Heuristic, not perfect: it cannot catch the model describing the user in
   unlabeled prose that does not open a sentence with their name.

6. Bundled default presets (added after the notes above)
   New list `bundledPresets` in lib/core/services/featured_presets.dart, JSON in assets/presets/:
     Shino + Personal (combined), No prompt, Mine, Be Yourself (new: main prompt tells the
     AI to use its own natural personality; all other blocks as in "No prompt").
   Seeded once per install by seedFeaturedPresets -> _seedBundledPresets (preset_seeder.dart),
   on new installs AND existing ones (pref bundledPresetSeeded_v1_<id>). No cover, no locked
   fields, never refreshed, and a deleted one is not put back.
   Existing installs that already imported these by hand will now have a second copy of each;
   delete whichever you do not want.
