SpicyChat 401 + character open fix (Oct 2026)

Problem
-------
Tapping any SpicyChat character showed:

  HTTP 401 - Unauthorized
  Invalid or expired token.

Root cause: prod.nd-api.com/v2/characters/{id} no longer accepts unauthenticated
requests. Community export scripts already require a captured Bearer token; the
Glaze public fetch did not.

For You / Recommended continued to fall back to the public Typesense trending
feed whenever the authenticated scrape returned no cards (session not ready,
or page layout change).

Changes
-------
1. spicychat_session.dart
   - SpicyChatSessionTools.readAccessToken(): walks localStorage/sessionStorage
     for a Kinde/Cognito-style access token (JWT or opaque under auth-ish keys).

2. spicychat_provider.dart
   - SpicyChatWebSession.getAccessToken() exposes that token from the headless
     session.
   - spicyChatFetchCharacter():
     a) Uses Bearer + x-app-id when a session token is available.
     b) On failure / no token, loads a partial card from the public Typesense
        collection (name, greeting, tags, avatar) so the character still opens.
     c) Last resort: bare CharacterData(name: id) so the UI never hard-fails
        with a 401 dialog.
   - Fallback Typesense scoped key updated to the current public key from the
     applications/spicychat config endpoint.

Usage
-----
- Sign in to SpicyChat in the app (Accounts / SpicyChat) so the WebView holds a
  real session. Character opens then get the full definition when the creator
  made it public.
- Guests still open characters with greeting + tags from Typesense (no full
  personality when the creator hid it — same as the site for logged-out users).
- For You still requires a signed-in session; if the scrape is empty it falls
  back to trending as before.

Build note: Flutter/Dart/Xcode are not available in this environment; source-only
patch. Rebuild the iOS app on a Mac / CI with Xcode.
