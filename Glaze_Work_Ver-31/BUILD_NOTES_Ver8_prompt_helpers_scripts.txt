Glaze WIP Ver8 — SpicyChat sign-in fix, saved-account fallback, Prompt Helpers, Scripts
(Written without a Flutter toolchain: nothing here has been compiled or run yet.
 Run `flutter analyze` first and send me anything it flags.)

1. SpicyChat sign-in reliability  (catalog/widgets/spicychat_login_sheet.dart)
   - REMOVED: the sheet wiped Google's cookies on every navigation to a Google
     page. Google's sign-in is several page loads, so each one threw away the
     session it had just created — the likely reason sign-in "sometimes" failed.
     Google is now only cleared once, when the sheet opens for a fresh sign-in.
   - ADDED: a watchdog. If the page never reports loaded (spinner stuck), after
     12 s (22 s when restoring) the sheet shows the page anyway.
   - ADDED: a "Done" button in the header. If auto-detection misses a finished
     sign-in, press it: it finishes if the page really holds a session.

2. Saved accounts  (catalog/services/spicychat_session.dart + login sheet)
   - A saved account now also stores that account's Google cookies.
   - Tapping it: restores the SpicyChat session + that Google session and tries
     to sign in automatically (as before).
   - If the saved session has expired, it opens the SpicyChat login page with
     Google's cookies kept, presses "Continue with <provider>", and if that
     button can't be pressed it outlines the button in pink so you only tap it,
     pick your Google account and press Continue.
   - Accounts saved before this build have no Google cookies; save them again
     (sign in once) to get this behaviour.

3. Prompt Helpers
   - New group "Prompt Helpers" in API settings, between Connection and Context.
   - New "Prompt Helpers" card in the chat Tools drawer (and the Tools tab).
     Both edit the same global setting (core/llm/prompt_helpers.dart,
     settings/prompt_helpers_provider.dart).
   - Formatting Helper, Enforce User Agency, Short/Medium/Long Response
     (the three lengths exclude each other). Anti-Slop was left out as asked.
   - They are sent as one system block at the end of the prompt
     ("[Response instructions]"), through the existing runtime prompt block path.
   - The setting is global, not per API config.

4. Scripts  (lib/features/scripts/)
   - Script Management: list with on/off switches and a "Running" badge, + menu
     (Add Directly / Import from URL / Import from File / Import from Greasyfork /
     Update All Scripts at Once), script details (Edit Code, Auto Update,
     Execution Scope, Whitelist, Blacklist, Matches, Grants).
   - Open it from: More menu -> Scripts, or the chat Tools drawer / Tools tab.
   - Scripts run in the Script Browser (globe button): a web view with an
     address bar. Scripts run on pages their @match/@include allow and anything
     they add to the page (panels, buttons) appears in it. GM_registerMenuCommand
     entries are under the lightning button. Supported: GM_getValue/setValue/
     deleteValue/listValues, GM_addStyle, GM_xmlhttpRequest, GM_setClipboard,
     GM_openInTab, GM_notification, GM_registerMenuCommand, GM_info, unsafeWindow,
     the GM.* promise versions, @require (downloaded at import), @run-at.
   - NOT done: scripts do not run inside the chat view or the provider login
     sheets — only in the Script Browser.
   - Greasy Fork import uses greasyfork.org's JSON endpoints; I could not test
     them from here.
