SpicyChat sign-in & full-site rendering fix
==========================================

Problems
--------
1. Embedded SpicyChat missed site headers / full chrome compared to the real
   mobile site (default Android WebView UA includes "wv"; SpicyChat + Google
   OAuth serve a degraded layout or block flows for that UA).
2. After signing in on the page, pressing Done still said
   "Not signed in yet — finish signing in, then press Done." Session was not
   detected or saved reliably (DOM-only probe was brittle; identity missed
   opaque auth tokens).

Fixes
-----
1. Shared Safari-like mobile user agent (no "wv") and mobile viewport settings
   via spicyChatWebViewSettings() / kSpicyChatUserAgent in spicychat_session.dart.
   Applied to:
   - Login sheet WebView
   - Account "View account" WebView
   - Headless SpicyChatWebSession (catalog / For You / Recent)

2. Stronger signed-in detection:
   - readIdentity now treats opaque tokens under auth-ish storage keys as
     signed-in, not only JWT strings.
   - probeController checks tokens/storage first, then improved DOM signals
     (premium, profile/account, avatar).
   - Login _probe and _manualDone prefer token/identity evidence; Done also
     accepts non-empty SpicyChat cookies after leaving the auth path.

3. Login sheet UX / session plumbing:
   - Gesture recognizers so the page scrolls like a normal browser.
   - cacheEnabled true (OAuth redirects are less flaky).
   - After a successful _finish, the headless web session is disposed so the
     next catalog request starts with the new cookies.

Files touched
-------------
- lib/features/catalog/services/spicychat_session.dart
- lib/features/catalog/services/spicychat_provider.dart
- lib/features/catalog/widgets/spicychat_login_sheet.dart

Build note: Flutter/Dart not available in this environment; changes are
source-only and were not compiled here.
