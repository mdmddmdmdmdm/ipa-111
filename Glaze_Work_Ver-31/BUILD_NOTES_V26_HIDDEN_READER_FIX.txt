Glaze v26: pop-ups, Daily Ranking numbers, Favorites
====================================================

1) Art taking over the screen while scrolling CrushOn (iOS)
   Real cause (from the screen recordings + the site opened in a normal browser):
   the cards autoplay short preview VIDEOS. In the reader's hidden iOS web view a
   playing <video> is handed to the system's full-screen player, which covers the
   whole app. Hiding the web view (the earlier attempt) can't stop that.
   Fix - the reader never plays media at all:
     * Dart (crushon_site_reader.dart): allowsInlineMediaPlayback, no autoplay
       without a tap, no picture-in-picture / AirPlay, and native content blockers
       that block every media request (resource type "media" and .mp4/.webm/.m4v/
       .mov/.m3u8/.mpd). One simple rule per extension: WebKit rules have no "a|b".
     * site_reader.js: HTMLMediaElement.play() is a no-op, autoplay/src/<source>
       are stripped from every <video>/<audio> (also ones added later), full-screen
       and picture-in-picture are refused, videos are visibility:hidden.
   Kept from the first v26 pass (harmless safety net): the hidden web view is
   recognised by a marker comment and kept invisible / off-screen
   (ios/Runner/AppDelegate.swift).

2) Daily Ranking numbers
   Cards now show the site's own badge: crown + number for 1-3, "#N" after that,
   then "Debut!" or the places gained/lost (up/down arrow + number).
     * site_reader.js reads the badge in the card's top-left corner.
     * If a page does not print one, the card is numbered by its place in the list.
     * New CatalogItem fields rank / rankNote (freezed: run build_runner so
       catalog_models.freezed.dart is regenerated), set in crushon_provider.dart,
       drawn by _RankBadge in catalog_card.dart. Only shown for CrushOn Daily Ranking.

3) Favorites
   Same path a person takes: Profile -> (first you see your own Characters tab) ->
   click the STAR tab -> Characters chip -> scroll down to the cards.
     * Starts on the home page and clicks the sidebar "Profile" link (falls back to
       any "Profile" control, then avatar menu).
     * "On the profile" = the Followers / Following / Interactions counters are on
       the page (the avatar menu prints the same words in a popup; those are ignored).
     * The icon row is the first row of >= 4 icon-only buttons BELOW those counters,
       so header icons (search, 18+, avatar...) can never be clicked by mistake. The
       GIF button at the far right is left out; the 4th icon is the star. A click is
       only accepted once the page shows the Characters / World Cards / Memories /
       Models / Folders chips.
     * If it still fails, the error now says why and lists the icons it saw.
   Tests: tools/crushon_reader_test/v26_test.py (python playwright) - mock of the
   screenshots: favorites, rank badges, video blocking. All pass.
